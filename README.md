# Grand Mobile Support Copilot

Сервис триажа обращений игроков Grand Mobile (Decentrathon 6.0, кейс 03). По каждой жалобе или репорту он определяет язык, категорию и приоритет, отсеивает спам и дубли, извлекает факты, готовит черновик ответа на языке игрока со ссылками на реальные пункты правил и решает, можно ли ответить автоматически или нужен администратор.

Сервис работает полностью локально и бесплатно. LLM подключается по желанию одной строкой в `.env` и вызывается только для тикетов, которые не закрываются шаблоном.

## Как это работает

```
тикет ─► нормализация (cp1251 → казахские буквы, токены <url>)
      ─► язык (ru / kk / uz / en / es / pt, в т.ч. транслит)
      ─► категория: точные правила → обученная модель → ключевые слова
      ─► приоритет p0–p3 по taxonomy.json
      ─► спам и дубли (один игрок, одна проблема, окно 60 минут)
      ─► факты: ник, пункты правил (заявленные игроком, не проверенные), доказательства, сервер
      ─► черновик: шаблон по ситуации на языке игрока + цитаты из rules.json
      ─► [LLM + RAG только для вопросов и неуверенных случаев, с проверками]
      ─► needs_human по жёстким правилам
```

**Категории без ручной разметки.** В данных нет категорий, но есть ответы администраторов. Из них восстанавливаются метки: код нарушения («2.1 ОП» → оскорбления, «5.2» → читы, «GZ/DM» → DM), вердикт (апелляции → жалоба на администратора) и типовые фразы («спешу на помощь» → помощь, «слежу за игроком» → жалоба через репорт). На этих метках учится модель TF-IDF + логистическая регрессия, которая видит только текст игрока ([copilot/weak.py](copilot/weak.py), [scripts/train.py](scripts/train.py)).

**Никаких выдуманных правил.** Цитата в черновике — это всегда дословный фрагмент пункта из `rules.json`, найденный по коду. Ответ LLM проходит проверку: можно ссылаться только на выданные ей пункты, любое другое упоминание номера правила отклоняет ответ, и остаётся шаблон ([copilot/rules.py](copilot/rules.py), [copilot/llm.py](copilot/llm.py)).

**Никаких обещаний.** Шаблоны не обещают разбан, возврат или наказание другого игрока, вердикт по жалобе выносит администратор. Ответы LLM с такими обещаниями отклоняются.

**Человек обязателен** для платежей, аккаунтов и взломов, жалоб на администраторов и апелляций, жалоб с доказательствами (вердикт выносит админ), просьб о помощи в игре, критичного приоритета и низкой уверенности модели.

**RAG.** Для черновика подбираются пункты правил, рекомендованные для категории в `taxonomy.json`, и найденные по тексту. Для вопросов о механике игры ищутся похожие вопросы в базе прошлых содержательных ответов администраторов ([copilot/rag.py](copilot/rag.py)).

## Запуск

На чистой копии репозитория достаточно одной команды:

```bash
make predict DATA=/путь/к/handout IN=tickets.jsonl OUT=pred.jsonl
```

При первом запуске она сама создаёт окружение `.venv`, ставит зависимости и обучает модели на `tickets_train.jsonl.gz` из папки `DATA` (около 5 минут, один раз). Моделей нет в репозитории: они получены из данных кейса, а публиковать данные и всё, что из них получено, запрещено. Если файла `tickets_train.jsonl.gz` нет, сервис всё равно работает, но только на правилах и менее точно. Файл `rules.json` нужен всегда: из него берутся цитаты.

Остальные команды:

```bash
make serve      # HTTP-сервис на :8000
make eval       # метрики на валидации -> artifacts/eval_report.md
make train      # полное обучение с отложенной проверкой и метриками
make test       # тесты
make install    # пересоздать окружение
```

По умолчанию `DATA` — это `../grand-support-copilot-handout-2026-10-27/handout`. Вместо `DATA=...` можно задать переменную окружения `COPILOT_DATA_DIR`.

### LLM (необязательно)

Скопируйте `.env.example` в `.env` и выберите провайдера:

| `LLM_PROVIDER` | Что это | Стоимость |
|---|---|---|
| `none` (по умолчанию) | только шаблоны | $0 |
| `anthropic` | Claude через официальный SDK | Haiku 5.5 ≈ $0.0003 за вызов |
| `openai_compat` | DeepSeek, Gemini, OpenAI или локальная Ollama | по прайсу провайдера, Ollama — $0 |

LLM вызывается только для вопросов и тикетов с низкой уверенностью классификатора. При таймауте (по умолчанию 4 с), ошибке или проваленной проверке остаётся шаблонный черновик. Ответ на вопрос уходит без администратора, только если опирается на похожий прошлый ответ админа; иначе черновик идёт на проверку.

`LLM_RPM` ограничивает число вызовов в минуту под тариф провайдера (бесплатный Gemini — 15). HTTP-сервис при выбранной квоте сразу ставит шаблон и не ждёт, а `make predict` ждёт свободный слот, чтобы каждый нужный тикет получил черновик от LLM.

## Интерфейс администратора

`make serve` и откройте http://localhost:8000. Это бонусная часть кейса: очередь, черновик и кнопки «отправить», «править», «эскалировать».

- Слева разделы «Ждут администратора», «Готовы к отправке», «Все обращения», «Эскалированы», «Отправлены». Счётчики стоят только у разделов, где нужно действие.
- Строка под заголовком сразу говорит, что срочно: сколько критичных обращений ждут ответа и какие.
- Карточка обращения: нужен ли администратор и почему, сообщение игрока, извлечённые факты, вероятный вердикт и черновик с дословными цитатами правил.
- Черновик можно править. Каждое решение (сохранить правку, отправить, эскалировать) записывается в `artifacts/feedback.jsonl`: исходный черновик, итоговый текст, категория и шаблон. Это обучающий сигнал для шаблонов и модели.
- По умолчанию очередь — выдуманный демо-набор [demo/tickets.json](demo/tickets.json): 16 обращений на русском, казахском, узбекском и английском. Свою очередь можно указать переменной `COPILOT_QUEUE=путь.jsonl`.
- На телефоне показывается одна область за раз: список, затем обращение.
- В карточке обращения есть блок «Как обработано»: язык, категория и чем она определена, приоритет и почему, повтор, вероятный вердикт, откуда черновик (шаблон, база ответов или LLM с временем и токенами), проверка ссылок, маршрут и время разбора. Ctrl+Enter в черновике отправляет ответ.

Чтобы отвечать быстро:

- **Группы.** Переключатель «Список / Группы» собирает обращения с той же темой, тем же ответом и языком. Клик по группе выбирает все её обращения, кнопка «Отправить N ответов» закрывает их разом: каждому уходит его собственный черновик.
- **Выбор нескольких.** Галочки в списке, «Выбрать все», Shift для диапазона. Текст можно изменить для всех сразу: `{ник}` заменится ником из каждого обращения.
- **Теги.** Тема, язык, приоритет, пункт правил, нарушитель, «без доказательств», повторы. Теги сочетаются между собой и с поиском; в карточке обращения они тоже кликабельны.
- **Похожие.** В карточке видно, сколько ещё обращений с таким же ответом и на этого же игрока.
- **Быстрые ответы** на языке игрока вместе с цитатами правил.
- **Отмена.** После отправки или эскалации 10 секунд можно нажать «Отменить».
- **Клавиатура.** `j`/`k` листать, `x` выбрать, `g` группы, `r` к черновику, `Ctrl+Enter` отправить, `e` эскалировать, `/` поиск, `?` подсказка.

Два раздела для проверки сервиса на своих данных:

- **Загрузка обращений.** Файл `.jsonl` или `.json` в формате выгрузки кейса (до 5000 обращений) или одна кнопка «500 обращений из валидации» (без ответов админов, как в скрытом тесте). Видно прогресс, скорость, время на обращение и сводку: куда ушли обращения, приоритеты, языки, категории, вызовы LLM. Все обращения попадают в очередь, где их можно открыть по одному.
- **Нагрузка.** 100, 500 или 1000 запросов на `POST /triage`, по 1, 10 или 50 одновременно. Запросы шлёт отдельный процесс ([copilot/loadgen.py](copilot/loadgen.py)), чтобы генератор не отнимал процессор у сервиса. Видно ошибки, p50 / p95, запросы в секунду, гистограмму задержки и самые долгие запросы с причиной.

Замеры на ноутбуке (один процесс, Gemini подключена, `LLM_RPM=14`):

| Проверка | Результат |
|---|---|
| Пачка из 500 обращений валидации | 17 с, 29 обращений в секунду; разбор p50 7 мс, p95 12 мс; 68 вызовов LLM, из них 56 сверх лимита в минуту получили шаблон без задержки |
| 500 запросов, по 10 одновременно | 2.3 с, 218 запросов в секунду, 0 ошибок; p50 34 мс, p95 48 мс; дольше 0.2 с — только 2 запроса с вызовом LLM (1.7–1.8 с) |

API интерфейса: `GET /api/queue`, `POST /api/tickets`, `POST /api/tickets/{id}/decision`, `POST /api/tickets/bulk`, `GET /api/quick`, `POST /api/batches`, `POST /api/batches/sample`, `GET /api/jobs/{id}`, `POST /api/loadtests`, `GET /api/loadtests/{id}`.

## Контракт

`POST /triage` и каждая строка `make predict` — по контракту из документа кейса. Запрос:

```json
{
  "kind": "complaint",
  "messages": [{"role": "player", "text": "оскорбил меня и семью в чате, 2.1", "attachments": 2}]
}
```

Принимаются и поля выгрузки (`ticket_id`, `created_at`, `region`, `server_lang`, `reporter_hash`, `reported_nick`, `rule_refs_raw`, `images_count`); `attachments` — число или список вложений. Ответ:

```json
{
  "ticket_id": null,
  "lang": "ru",
  "category": "complaint.insult",
  "priority": "p2",
  "is_spam_or_duplicate": false,
  "extracted": {"nickname": null, "rule_refs": ["2.1"], "has_evidence": true, "server": "cis"},
  "draft_reply": {
    "lang": "ru",
    "text": "Здравствуйте! Ваша жалоба принята к рассмотрению. Предполагаемое нарушение: ОП 2.1. Администратор проверит доказательства и вынесет решение; жалобы рассматриваются в течение 48 часов.\n\nС уважением, администрация Grand Mobile.",
    "cited": ["2.1", "ЖБ 1.4.1"]
  },
  "needs_human": true,
  "confidence": 1.0,
  "reasons": ["категория: модель (1.00)", "приоритет: нарушение с доказательствами", "вероятный вердикт: approved (0.91)", "вердикт по доказательствам выносит администратор"]
}
```

Ссылки в `cited` и `rule_refs` записаны как в `taxonomy.json`: пункт общих правил — номером (`2.1`), правила жалоб и зелёной зоны — с кодом (`ЖБ 1.2.2`, `GZ 1.1`), остальные разделы — полным названием (`Правила для ОПГ 1.2`). `server` — это регион. После полей контракта ответ содержит расширенные поля для интерфейса и отчёта: цитаты с текстом пункта (`draft.citations`), отдельные `is_spam` и `is_duplicate`, причины для администратора (`needs_human_reasons`), вероятный вердикт, сведения о вызове LLM.

### Ограничения

- Категорий в данных нет, метки восстановлены из ответов администраторов. Метрика категории — прокси: часть меток построена по тем же ключевым словам, что видит модель, поэтому реальная точность может быть ниже.
- Модель вердикта угадывает решение админа в 60% случаев (скриншоты ей недоступны). Поэтому она используется только как подсказка и только при высокой уверенности, а такие черновики всё равно подтверждает администратор.
- Поле `lang` в данных помечает украинский текст (буква «і») как казахский. Наш детектор отличает их, и таким игрокам сервис отвечает по-русски.
- Казахские и узбекские шаблоны не проверены носителями языка.
- Разметки приоритетов нет, приоритет назначается по правилам `taxonomy.json`.
